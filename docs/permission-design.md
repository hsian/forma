# 账号与权限管理设计稿

状态：账号与权限管理已实现。系统账号保留 admin/member，项目授权通过角色和操作权限管理，旧角色兼容迁移。研发工作项属于后续范围。

## 目标与边界

先完成账号、项目成员和角色权限的管理，再接入研发迭代、需求、任务与 Bug。现有项目和权限必须平滑迁移。原型版本是内容快照，研发迭代是排期容器，两者保持独立。

本期提供按操作配置的项目角色；不引入部门树、页面级授权、字段级权限、条件表达式或审批流程。管理界面只展示已实现的模块，避免出现无效配置。

## 权限模型

系统层与项目层分开。系统层负责账号、系统管理及创建项目资格；项目层负责项目内的内容和成员管理。

系统管理员可以访问所有项目，其权限来源必须在界面明确标注。普通成员必须加入项目才能访问，拥有系统账号不代表拥有所有项目权限。已有普通成员的创建项目能力迁移时保留，新增账号可由系统管理员配置是否允许创建项目。

项目所有者是责任归属，仅一人；所有者具有完整项目管理权限。转交所有权是独立操作，必须选择有效项目成员并二次确认，不能通过取消成员角色间接完成。系统必须始终保留至少一个可登录的系统管理员。

项目成员本期只分配一个角色。角色由一组明确的操作权限构成，服务端统一检查权限，前端使用同一份权限标识决定入口状态。暂不支持对某个成员单独加减权限，也不叠加多个角色，避免授权来源难以解释。

## 默认角色与权限矩阵

默认角色为只读成员、原型设计者、版本负责人、项目管理员。角色描述必须解释用途，不能只给技术名称。

| 操作 | 只读成员 | 原型设计者 | 版本负责人 | 项目管理员 |
| --- | --- | --- | --- | --- |
| 查看项目、原型和版本 | 是 | 是 | 是 | 是 |
| 编辑原型内容、使用 AI 编辑 | 否 | 是 | 是 | 是 |
| 新建、重命名、移动和复制页面 | 否 | 是 | 是 | 是 |
| 删除页面及其子页面 | 否 | 否 | 否 | 是 |
| 导入 Sketch | 否 | 是 | 是 | 是 |
| 从版本复制新项目 | 否 | 是，且允许创建项目 | 是，且允许创建项目 | 是，且允许创建项目 |
| 确认固定原型版本 | 否 | 否 | 是 | 是 |
| 删除固定原型版本 | 否 | 否 | 否 | 是 |
| 修改项目基本信息 | 否 | 否 | 否 | 是 |
| 添加、移除成员和分配角色 | 否 | 否 | 否 | 是 |
| 创建、修改项目自定义角色 | 否 | 否 | 否 | 是 |
| 删除项目、转交所有权 | 否 | 否 | 否 | 仅所有者或系统管理员 |

这些是新项目的默认模板，不直接改变旧账号的能力。旧 editor 映射为兼容角色，保留原有删除页面能力；旧项目 admin 也保留原有项目删除能力，不能在无提示下收紧。默认角色的新规则通过明确迁移提示或新建项目生效。

项目管理员可复制默认角色形成自定义角色，例如“可编辑但不能导入”的外部协作角色。管理员内置角色不可删除或修改。自定义角色不能获得所有者或系统管理员的专属能力。

权限配置按模块分组：原型页面、原型版本、项目设置、成员与角色。勾选编辑或管理操作时自动包含必要的查看权限，并解释依赖。撤销查看权限时明确提示将同时撤销哪些操作。不能以单独一个“可编辑”勾选替代所有操作。

允许管理角色的用户能够间接获得这些角色的全部权限，因此第一版只允许完整项目管理员管理成员及角色，不把这项能力单独下放给自定义角色。

## 管理界面

从账号菜单跳转到独立的 /manage 管理中心页面，拥有自己的顶部导航、项目选择和侧边导航，内容区域适应窗口并支持滚动。进入前保存原型并释放编辑占用，返回时恢复原来打开的设计页。系统管理与当前项目管理分别成组，每个页面明确显示作用范围。

### 项目成员

默认只显示已加入当前项目的成员，不把所有系统账号当作项目成员混排。提供用户名搜索、角色筛选、成员数量、添加成员按钮。列表显示头像缩写、用户名、角色、授权来源和操作。

添加成员使用独立面板：搜索现有账号、选择角色、展示角色能力摘要、确认加入。加入与取消必须有明确结果。当前角色变更采用“选择—确认保存”，不在下拉框每次变化时立即提交。

移除成员需要确认，提示其将失去当前项目访问权；系统管理员和项目所有者显示固定身份及不可修改原因。转交所有权放在项目设置的独立区域。

### 角色与权限

左侧角色列表显示名称、说明、内置或自定义标记、使用人数；右侧显示按模块分组的权限矩阵。支持复制角色、编辑自定义角色、查看使用此角色的成员。

修改前后展示新增和撤销的权限以及受影响人数，保存成功后刷新生效权限。删除正在使用的角色时必须先选择替代角色，角色替换和删除应在同一事务内完成。

成员详情可查看其最终权限以及来源，例如“来自项目角色：原型设计者”或“系统管理员拥有全部项目权限”。本期无需制作模拟其他用户的登录功能。

### 系统账号

仅系统管理员可进入。展示搜索、账号身份、启用状态、创建时间及创建账号入口。创建账号和加入项目是两个动作；创建成功后可以继续选择项目与角色，不能默认加入全部项目。

支持停用与重新启用、重置密码。停用立即使已有会话失效并释放编辑占用；重置密码使旧会话失效。禁止停用自己或最后一位可用系统管理员。密码在后端处理，不在日志、审计和列表中保留明文。

### 权限变更记录

记录操作者、时间、项目范围、目标成员或角色、操作类型及变更前后摘要。账号生命周期记录仅系统管理员可见，项目权限记录仅对应项目管理员及系统管理员可见。界面支持按成员与时间筛选。

审计覆盖授权、撤权、角色修改、账号创建与停用、密码重置和所有权转交。密码重置只记录发生过，不记录密码。

### 交互品质

首次加载、无成员、搜索无结果、请求失败分别处理。错误出现在相关表单内，并保留输入。变更时禁用正在提交的操作，避免重复提交；成功后明确提示生效范围。离开未保存的权限配置时提示保存或放弃。

不允许操作时给出具体原因，例如“仅项目所有者可以转交项目”，而非统一提示“无权限”。权限已撤销导致当前页面无法继续访问时，引导返回可访问项目，处理未保存内容时不能假装保存成功。

## 实现要求

- 使用稳定的操作标识，例如 prototype.read、prototype.edit、page.delete、version.publish、member.manage；显示文案与标识分离。
- 为角色、角色权限、成员角色、账号状态、权限变更记录建立持久化结构。迁移保留旧账号、项目归属和原有能力。
- 服务端按当前数据库中的有效身份和权限逐次授权，撤权后旧登录会话不能继续提交写入；不能只依赖登录时缓存的角色。
- 权限变化与审计记录在同一事务提交。成员被移除、停用或失去编辑能力时释放其编辑占用。后续保存仍须重新校验权限。
- 同页编辑占用继续独立于角色权限存在。拥有编辑权限不代表可以覆盖其他人正在编辑的页面。
- 成员管理接口避免向普通项目管理员暴露不必要的系统账号信息；添加成员所需的账号查询仅返回身份摘要。
- 自定义角色在项目内生效，不能跨项目引用或修改；所有查询、变更和审计访问必须验证项目归属。

## 后续工作项权限的扩展

研发模块上线后，在相同角色编辑器里增加研发迭代、需求、任务、Bug 权限组。产品、开发、测试作为职责模板，不能因为名称自动获得未明确授权的操作。

需求关联原型版本时，同时校验源需求和目标项目版本的访问权限，不能通过关联接口绕过目标项目权限。关联本身不向用户授予原型访问权。初期优先支持同项目关联。

## 交付与验收顺序

1. 角色与操作权限基础、兼容迁移、服务端授权及回归测试。
2. 项目成员与角色管理界面、权限摘要及变更确认。
3. 账号状态与密码管理、授权审计及所有权转交。

验收必须覆盖跨项目越权、角色依赖、旧数据迁移、即时撤权、角色删除替换、管理员保底以及并发保存。前端按钮状态与后端拒绝结果必须一致。完成这些能力后再增加研发工作项。
