# 业务应用改造：结构与后续边界

当前已建立模板工程、逐页 React 模块生成与保存后自动同步，后续逐步把原型演示升级为业务应用。现阶段不宣称已经实现无人工业务开发。

## 当前结构

`shared/application.ts` 登记模板与项目工程元数据；`templates/admin/` 是开发者可维护的管理后台骨架，`templates/runtime/request.ts` 是统一请求基础能力。模板引擎在 `server/application-workspace.ts`，负责独占创建目录、复制模板、固定直接依赖和运行器、写入项目标识以及同步快照。数据库只记录工程关联与同步时间，业务工程在文件系统中。

新建时数据库事务包含工程初始化，初始化出错时回滚项目与页面并清理本次新建的目录。已有目录始终拒绝复用。进程被强制终止或断电不具备跨数据库与文件系统的分布式事务保证；若留下未关联目录，应由维护者核对后处理，系统不会自动覆盖它。

`server/application-codegen.ts` 为每页生成独立的 `.tsx` 模块，并维护按需加载路由；页面定义保留 TypeScript 类型，共同引用固定的运行器，没有将交互逻辑复制到每页。`.forma/generated-files.json` 记录文件哈希。生成前检查全部受管文件（包括待删除文件）的手写修改，确认无冲突后逐文件使用临时文件替换，最后清理旧名称或已删除页面的受管文件。多文件不具备文件系统事务；写入失败会尝试恢复已修改文件，记录未能恢复的文件并保留待生成任务以便重试。

SQLite 触发器把 linked 项目的文档和页面树变化写入 `application_sync_state`，与原修改共享事务；回滚不会留下任务。`server/application-sync.ts` 在响应后合并任务并定时补查，包括普通保存、AI、导入与直接数据库写入。同步按快照记录修订号，成功只确认已发布的修订号，期间发生的新变化仍待处理。生成失败不改变页面保存结果，错误持久保存，自动退避重试；项目删除级联删除任务并保留源码。启动时对既有工程补齐页面源码。

同步前校验目录、符号链接与项目标识，拒绝向其他项目的工程写入。自动同步随获授权的页面修改触发；手动重试权限沿用 `project.update`。同步不会安装依赖、执行项目代码或升级共享运行器。旧工程原始入口自动接入生成路由，包含自定义修改的入口保留并提示维护者接入。

当前多个页面通过同一个运行器解释页面配置，生成区域与手写区域严格分开。每次初始化的运行器从平台当前源码复制，模板维护者修改运行语义或依赖时应更新模板版本。已有工程不会静默升级运行器；升级与兼容检查作为独立功能实现。

## 后续阶段

中间区域现已接入第一阶段真实工程预览：`server/application-runtime.ts` 按项目管理独立 Vite 子进程，`scripts/application-preview.mjs` 加载项目自身依赖与配置，`src/ApplicationRuntimePreview.tsx` 提供运行状态、iframe、停止、刷新与错误展示。只允许维护者启动或停止，HTTP 模块和资源转发继续校验项目读取权限。使用 `/__forma_runtime/:projectId/` 前缀避开业务项目常见的 `/api` 代理；子服务仅绑定回环地址。

当前没有 WebSocket 转发：子服务关闭 HMR，父编辑器在发布修订号变化时重新加载 iframe。开发期错误报告与组件选择桥接仅注入管理的预览，不进入导出的业务源码。`scripts/application-preview-bridge.js` 通过既有 `data-preview-id` 绘制浮层，在选择模式捕获点击，在体验模式保留业务交互；不修改业务 DOM 或接收可执行补丁。父窗口校验消息来源窗口、来源域、页面编号和当前文档中的元素编号，再使用原有 store、权限与保存流程更新属性。加载新 iframe 后重新发送模式和选中状态。弹窗可选中，但保存重载仍会关闭临时弹窗和清空输入。拖拽与缩放桥接尚未接入。编辑画布的 DOM 与状态继续保留，可切回画布。空闲与关闭时清理自有进程，外部手动启动的服务不纳入管理。

1. **布局与页面语义**：添加容器、嵌套、Flex/Grid、字段和表单模型，明确自由画布向业务布局的迁移规则。保证编辑器与业务应用共用运行逻辑。
2. **接口契约**：项目级接口中心，导入 OpenAPI，管理环境、请求与响应适配；统一维护类型与接口调用函数。模拟与真实接口使用同一契约。
3. **数据与动作**：组件绑定、加载与错误状态、分页、校验、提交、刷新和路由参数；声明式动作先于任意脚本，服务端校验所有引用。
4. **公共业务能力**：注册组件和函数的稳定标识、类型、用途与引用关系；区分实例修改、公共定义修改和解除引用。现有「我的组件」仍是副本插入，不能作为公共组件引用机制。
5. **AI 生成与验证**：生成前检索公共能力，约束依赖方向；修改公共模块时计算影响范围，执行类型、引用与关键流程检查。业务生成不得直接修改平台底座。
6. **版本交付**：页面、接口契约、模板版本和源码提交组成统一发布清单；支持构建预览、发布、回退和显式模板升级。

平台公共能力 → 模板能力 → 项目公共能力 → 页面业务，依赖只从页面向底座流动。项目公共能力不依赖具体页面；相似外观但含义不同的业务组件保留独立封装，避免无边界的通用组件。

## 验收目标

选择一个真实管理模块，完成查询、新增、编辑和后台权限衔接；业务代码无需人工编写。连续修改需求、加入第二个复用模块、修改公共组件后，两个模块均通过关键流程检查，并能独立构建、部署和回退。
