# 接口适配

每个业务域建立一个目录，按接口导出 `defineEndpoint` 定义的能力。统一使用 `request` 处理网络、超时、取消与 HTTP 错误；`adapt` 对各自接口做运行时校验、业务成功判断和字段提取，可抛出 `BusinessError`。不要全局假定 code=0、success=true 或 data.records。

请求参数由 `request(input)` 映射；路径参数必须编码。分页、日期、字典、空值均按接口文档显式转换。返回页面需要的业务类型，不让页面读取原始响应路径。详情、新增、修改可以分别使用不同响应格式。

身份凭据与登录失效处理只在 `request.ts` 配置。不同后端可通过 `createRequest` 建立命名客户端，适配器统一调用对应客户端。不要在各页面读取或拼接 Token。

`withMock` 只在明确启用时使用模拟实现；真实请求失败不能静默回退成模拟成功。后端接口变更时更新适配和测试，稳定的业务能力 ID 尽量保持不变。在 `docs/api-integrations.md` 记录来源、方法/路径、映射、成功规则与待确认项。
